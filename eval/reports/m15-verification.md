## 구현 내용

- [사례 목록](../cases.md)과 [manifest](../cases.json)은 여섯 유형을 각각 대표 유형으로 배정합니다. 혼합 프로파일이 있어도 같은 사례를 여러 유형의 사례 수로 중복 계산하지 않습니다.
- [평가 도구](../../scripts/evaluate.py)는 노드 ID 대신 실제 역할의 코드 이름·종류·소스 위치로 대응시키고, 필수 관계의 방향·유형·확신 수준을 비교합니다. 현재 필수 역할은 48개, 관계는 29개입니다.
- 누락·중복 역할, 잘못된 호출 관계, 불확실성의 확정 전환, 순서 없는 사례의 재생, 소스/질문/범위 불일치, 근거 실패를 보고합니다. 추가 노드·관계는 자동 사실 판정 없이 사람 검토 대상으로 남깁니다.
- 후보마다 실제 고정 소스의 깨끗한 Git 상태·커밋과 근거 해시/앵커/범위를 재검사합니다. Git에서 무시한 근거 파일의 변경도 검출합니다. 대상 프로그램과 모델 API는 실행하지 않습니다.
- 누락된 후보 파일도 실패한 사례로 결과에 남기고 재현율 분모에 포함합니다. 여섯 저장소가 서로 다른지 확인해 같은 저장소를 이름만 바꾸어 수를 늘리지 못하게 합니다.
- 결과·사람 답변 보호를 위해 기존 출력 디렉터리를 덮어쓰지 않습니다. 검토 답변은 후보·정답·지침/렌더러/평가 도구/루브릭의 해시에 묶으며 변경 후 재승인을 요구합니다. IR의 `humanReviewed`만으로 승인하지 않습니다.
- 생성 시점·모델과 출처는 입력에서 기록하고, 실제로 계측하지 않은 토큰·비용·생성 시간은 null입니다. 평가 실행 시간과 근거 범위의 양을 별도로 기록합니다.

## 실행 확인

- Python 전체 검사: 76개. 평가 전용 31개에는 로컬 Git 통합 검사, 잘못된 관계·범위·근거, 검토 만료·미서명 승인·수동 치명적 오류, 누락 사례 집계, 부분 비교, 출력 보존, 엄격 게이트 종료 코드가 포함됩니다.
- Playwright 전체 검사: 136개, 데스크톱 1440×1000 및 좁은 화면 390×844. 추가 18개 페이지를 두 화면에서 열어 공통 캔버스·근거 패널·오프라인 동작·노드 겹침·화살표 끝점·가로 넘침·재생 없는 사례를 검사했습니다.
- 18개 소스 후보: 자동 통과 18개, `complete` 12개 / `partial` 6개, 사람 승인 0개. 작은 유틸리티와 정적 등록 확인도 정상 결과로 유지했습니다.
- `--strict` 전체 실행: 사람 검토 대기 때문에 종료 코드 1, 상태 `pending-review`. 일반 자동 검사 성공과 최종 승인을 구별했습니다.
- 직전 전체 실행과 최종 실행 비교: `no-regression`. 이 결과는 사람 검토를 통과했다는 뜻이 아닙니다.

명령과 실행 조건은 [임시 베이스라인](../runs/2026-09-06-baseline.md), 실제 사용 절차는 [평가 가이드](../../docs/evaluation.md), 사람 판정 기준은 [루브릭](../rubric.md)에 있습니다. 검증 과정의 전체 HTML과 출력은 `build/eval/`에 두고 Git에서 제외했습니다.

## 남은 게이트

같은 코딩 에이전트가 분석과 정답 후보를 작성했습니다. 독립적인 검토자가 고정 소스와 정답 후보를 대조하고, 처음 보는 독자가 실제 페이지의 목적·입력·결과·동작·한계를 이해하는지 확인해야 합니다. 현재 재실행은 독립 모델 생성 18회의 실험이 아니므로 탐색·생성 성능의 베이스라인으로 해석하지 않습니다. 이 검토를 반영해 승인 기준을 확정한 다음 M2의 복합 동작 6개 추가와 24개 회귀 평가로 이어집니다.
