# M2 구현·자동 검증 기록 — 2026-09-06

복합 동작 탐색 지침, 경로·조건·실행 방식 표시, 필수 행동 주장·경로 평가를 구현하고 유형별 복합 사례 6개를 추가했습니다. **구현과 자동 검증을 완료했으며 독립적인 사람의 사실·이해도 검토는 대기 중**입니다. M1/M1.5의 미승인 상태도 유지합니다.

이 문서는 최초 M2 구현 시점의 기록입니다. 이후 [자동재생 표시 수정](m2-playback-verification.md)과 [병렬 진입 연결 수정](m2-parallel-handoffs-verification.md)을 반영한 결과가 현재 `build/eval/m2/`에 있으며, 이 문서의 실행 결과는 `build/eval/m2-before-playback-fix/`에 보존했습니다.

## 구현

- `code-flow` 0.3.0: [복합 동작 지침](../../skills/code-flow/references/complex-behavior.md)을 필요한 경우 읽도록 연결하고 여섯 프로파일의 분기·반복·확장·실패 규칙을 보완했습니다.
- 공통 스키마의 아직 동결되지 않은 0.1.0 초안에 선택적 step `condition`과 `execution`을 추가했습니다. 기존 입력은 그대로 유효하며, 메타데이터도 단계의 근거·검토 상태를 따릅니다. 스키마·지침 변경은 기존 해시 기반 검토를 만료시킵니다.
- 화면은 기존 `scenario.kind`와 `step.branch`, 새 조건·실행 방식을 표시합니다. parallel/unordered 단계는 명시적 연결도 정적으로 유지하며 인접 노드 단계 사이에 순차 이동을 추론하지 않습니다. 다음 단계에 없는 조건·표시는 남기지 않습니다.
- 에이전트 예시는 핵심 7개를 먼저 보여 주고 도구 선택·래퍼·구현 경계는 상세 보기에서 표시합니다. 재생이 상세 대상을 가리키면 실제 노드를 드러냅니다.
- 평가기는 18개와 24개 manifest를 모두 지원합니다. M2의 행동 기준은 역할·근거 위치·검토 상태·분기·조건 유무·실행 방식으로 비교합니다. 필수 경로는 같은 시나리오의 역할 순서를 확인하고 추가 설명 단계를 허용합니다. 문구나 노드 ID 일치를 정답으로 삼지 않습니다.
- `compare --allow-suite-extension`은 전체 실행끼리의 사례 추가를 명시적으로 비교합니다. 기존 소스·정답·분류를 바꾸거나 기존 사례를 빼거나 추가 사례가 실패하면 통과하지 않습니다. 보존한 M1.5 manifest와 원장은 현재 24개 구성을 실수로 줄이지 않도록 분리했습니다.

## 남은 검토

이 실행은 저장된 후보 재검증입니다. 실제 대상 프로그램·모델 호출·독립 모델 생성은 수행하지 않았고 생성 비용·토큰은 추정하지 않았습니다. 필수 경로와 근거 위치가 맞아도 모든 캡션·숫자·조건의 사실성이 자동 증명되지는 않습니다. 같은 코딩 에이전트가 작성한 후보와 정답을 독립적인 사람이 검토하고, 처음 보는 독자의 이해도를 확인해야 승인 베이스라인이 됩니다.

다음 개발 범위는 M3의 규칙 탐색·조건 비교·이유 설명과 동작 페이지 연결입니다. 현재 규칙 카드와 시나리오 조건이 M3의 전체 자유 형식 해설 워크플로를 대신하지 않습니다.
