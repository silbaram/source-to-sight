# M2 병렬 구간의 진입·호출 연결 수정 — 2026-09-06

`도구 묶음이 정상 완료된 한 단계`의 3→4단계에서 실제 `process-batch` 연결이 있어도 이동 점과 방향 안내가 사라지는 문제를 재현했습니다. 앞선 진행 막대·노드 강조 수정은 이 연결 누락을 해결하지 못했습니다. 병렬·순서 미정 단계를 일괄 차단한 재생 조건과, 진입 연결 대신 도착 노드만 지정한 시나리오가 원인이었습니다.

## 변경

- 시나리오에 명시한 `edgeId`는 병렬·순서 미정 구간에서도 근거가 확인된 호출·전달·기록 관계를 따라 움직입니다. 노드 설명만으로 병렬 경계를 넘는 연결이나 작업 사이의 실행 순서를 추론하지 않습니다.
- 에이전트 정상 시나리오에 이미 존재하는 진입, 작업별 도구 호출, 관찰 기록, 다음 반복 연결을 명시했습니다. 새 그래프 관계는 추가하지 않았고, 진입·일반 도구 호출 단계의 근거에 호출부 위치를 포함했습니다.
- 등록·의존 관계와 추정·위치 미확인 주장에는 이동을 허용하지 않습니다. 모션 감소 설정도 유지합니다.
- 작성 지침과 렌더러 계약에 병렬 작업 사이의 순서와 확인된 호출 방향의 차이를 반영했습니다.

3→4단계는 **모델 요청과 도구 처리 → 도구 묶음 제출과 수집**으로 이동합니다. 다음 단계는 작업별 호출 관계를 설명하고, 결과 기록은 묶음 처리기에서 관찰 기록으로, 다음 반복은 반복 제어의 기존 자기 연결로 표시합니다. 실제 작업들의 시작·완료 순서를 재현하는 애니메이션은 아닙니다.

## 후속 확인: 노드 패널의 중복 문장

`실행 설정과 요청 기록` 노드의 설명과 확인 메모에 같은 문장이 들어 있어 패널에서 두 번 노출되는 문제를 수정했습니다. 24개 후보 중 38개 노드가 같은 형태였습니다. 공통 뷰어는 공백을 정리한 확인 메모가 이미 표시한 제목·설명과 같으면 추가 문단을 생략합니다. 다른 확인 내용과 근거 위치·상태는 유지합니다. 후보·정답 데이터는 변경하지 않았습니다.

이 확인 당시 `build/eval/m2/`에 중복 문장 수정을 반영했습니다. 위 진입 연결 수정 당시의 실행은 `build/eval/m2-before-panel-copy/`에 보존했습니다. 예시 11개·M1 6개도 같은 템플릿으로 갱신했습니다. 패널·캔버스·24개 평가 페이지에 대한 기존 브라우저 검사 **136개**가 통과했고, 소스 기반 평가 **24/24 자동 통과**, 직전 실행 대비 `no-regression`을 확인했습니다. 모바일·데스크톱에서 문제 문장이 한 번만 보이고 두 근거 위치와 별도 확인 메모가 유지되는 것을 직접 확인했습니다. 화면과 확인 결과는 임시 `build/qa/panel-copy/`에 있습니다.

이후 [부드러운 화면 이동](smooth-camera-verification.md)을 반영하면서 중복 문장 수정 당시의 실행은 `build/eval/m2-before-smooth-camera/`에 보존했습니다. 현재 `build/eval/m2/`는 두 수정이 모두 적용된 결과입니다.
