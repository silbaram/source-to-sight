## 이번에 가능한 것

호스트 에이전트가 사용자의 질문에서 설명 대상과 범위를 정하고, 실제 소스를 읽어 역할·호출·등록·상태·외부 경계를 추적한 뒤, 근거를 확인한 HTML을 만들 수 있도록 `code-flow`를 구현했다. 분석은 스킬을 따르는 에이전트가 수행한다. `author.py`와 렌더러는 자연어 주장을 자동으로 판정하는 분석기가 아니다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| `author.py doctor` | 필수 참조·프로파일·템플릿·글꼴·라이선스와 두 스키마 확인 |
| 스킬 `quick_validate.py` | `code-flow`, 기존 `visual-primer` 모두 통과 |
| `npm run m1:sources` | 공개 저장소 여섯 곳을 고정 커밋의 Git 체크아웃으로 확보. 대상 프로그램 실행 없음 |
| `npm run m1:examples` | 실제 소스의 근거 범위 22개 위치·해시 재확인, HTML 여섯 개와 출력 JSON 생성 |
| `npm test` | **45개 통과**: 렌더러 계약 28개 + 작성 도구 12개 + 소스 다운로드 5개 |
| `npm run test:browser` | **100개 통과**: 렌더러 50개 + M1 16개 + 공통 캔버스 34개 |
| 문서·출력 검토 | 내부 문서 연결, 스킬 번들 내 참조, 소스 앵커 비노출, 출력 스크린샷 확인 |

작성 도구 검사에는 단독 설치, 입력 초안 보호, 범위별 식별자, 잘못된 경로/심볼릭 링크/범위, 중복 근거, 변경된 커밋, 변경된 파일의 신뢰 하락, 다른 저장소·주제 출력 충돌, 같은 저장소의 재검토된 새 커밋으로 갱신, 인증 정보 없는 저장소 식별이 포함된다. Git 저장소 안의 무관한 소스 아카이브가 바깥 저장소 커밋을 물려받지 않는지도 확인했다. 다운로드 검사는 fetch 중단 및 init 직후 중단에서 재시도하고, 로컬 파일·다른 origin·변경된 체크아웃을 보존하는지 로컬 Git 저장소로 확인한다.

연결 페이지의 소스 비교는 양쪽 페이지가 근거로 사용한 파일 전체를 현재 소스 루트에서 다시 읽고 해시를 비교한다. 실제 Git 저장소에서 `.gitignore` 대상 설정 파일만 변경·삭제하거나 외부 파일을 가리키도록 바꾸어도, 커밋과 clean 표시가 같은 상태에서 불일치 경고가 나오는지 검증했다. 두 페이지가 서로 다른 근거 파일을 사용하거나 이전 출력에 `observedContentHash`가 없어도 적용된다. 일치하는 추적 파일이나 변경되지 않은 제외 파일은 불필요한 경고 없이 연결하며, 현재 페이지의 유효한 주장과 기존 연결 파일은 보존한다.

브라우저 검사는 Chromium 1440×1000 및 390×844에서 오프라인 로딩, JavaScript 오류와 외부 요청, 문서 가로 넘침, 노드 겹침, 선의 다른 노드 관통, 실제 화살표 접점, 근거 패널과 상태 조건을 확인했다. 한 노드 유틸리티와 순서 없는 이벤트 설명은 재생 제어를 만들지 않는다. 알려진 디스패치 규칙과 미확인 대상의 상태가 서로 다를 수 있음을 검사한다.

## 남은 게이트와 후속 범위

[계획](../../plans/source-to-sight-evolution-plan.md)의 M1 게이트는 유형별 근거를 사람이 최대 다섯 개(적으면 전부) 확인하고, 해당 코드를 모르는 사람이 목적·입력/결과·주요 동작·중요한 제한을 설명할 것을 요구한다. [검토 자료](m1-human-review.md)는 확인할 원본 위치와 연결된 주장, 답변란을 제공하지만 검토자·판정·이해도 답변은 비워 두었다. 이 조건을 자동 검사로 대신하거나 M1 최종 완료로 표시하지 않았다.

현재 사례는 작성 에이전트가 소스를 읽고 결과도 작성했다. 세 사례는 M0 구조를 재사용해 재검토했으며, 세 사례는 새로 추적했다. 독립적인 모델의 블라인드 평가나 일반 저장소에 대한 정확도 측정은 아니다. M1.5의 열여덟 케이스·사람이 확인한 정답·기준선 평가는 후속 범위다.

승인한 캔버스 UI와 다크모드를 공통 생성 템플릿에 적용하고 M0·M1 결과를 다시 생성했다. 검색·이동·확대·구성/흐름 전환과 선택 시 근거 패널은 실제 IR을 사용한다. [캔버스 적용 기록](canvas-viewer-verification.md)을 참고한다. 규칙 설명의 전체 탐색은 M3, 프로젝트 전체 지도 탐색은 M5에 남아 있으며, 같은 UI를 사용해도 행동 설명의 분석 범위는 그대로다.
