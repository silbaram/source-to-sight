# 노드 사이의 부드러운 화면 이동 — 2026-09-07

노드 선택과 설명 단계 전환이 스크롤 좌표를 즉시 바꾸어 다음 위치를 따라가기 어려운 문제를 수정했습니다. 공통 뷰어가 현재 위치에서 다음 노드 또는 연결까지 약 360 ms 동안 부드럽게 이동합니다. 이미 보이는 대상은 화면을 유지하고, 필요한 페이지 스크롤과 축소도 같은 이동 안에서 처리합니다.

자동재생은 화면이 도착한 뒤 연결 표시와 1.5초의 단계 설명 시간을 시작합니다. 이동 중 정지하면 현재 위치에서 멈추고, 이어 재생하면 필요한 이동을 마친 뒤 설명을 계속합니다. 직접 스크롤·드래그·방향키 조작은 자동재생을 멈춥니다. 창 크기가 바뀌면 이전 목적지를 취소하고 새 화면에 맞추며, 모션 감소 설정에서는 즉시 위치를 표시합니다. 상세 노드를 펼치는 단계는 연결의 출발 노드 위치를 유지한 뒤 이동합니다.

## 검증

| 검사 | 결과 |
| --- | --- |
| 화면 이동 브라우저 검사 | 16개 통과; 중간 위치, 도착 후 연결 표시, 정지/재개, 빠른 이전/다음, 직접 이동, 모션 감소, 창 크기 변경, 상세 노드 전개 |
| 전체 브라우저 검사 | 216개 통과; 1440×1000 / 390×844 |
| Python 전체 | 86개 통과 |
| 소스 기반 평가 | 24/24 자동 통과, 직전 실행 대비 `no-regression` |
| 설명 데이터 보존 | 후보·정답 해시 24쌍 모두 동일 |
| 실제 시간 재생 | 데스크톱 1327×921에서 패널을 연 상태와 모바일 390×844에서 정상 시나리오 8단계 확인 |

실제 시간 검사에서 이동마다 21~22개의 서로 다른 중간 위치를 관찰했습니다. 화면 이동 중 연결 표시가 먼저 시작되거나, 도착 뒤 현재 연결의 노드가 가려지는 프레임은 없었습니다. JavaScript 오류도 없었으며 이동 중·도착 후 화면을 확인했습니다. 원본 화면·프레임 기록·동영상은 Git에서 제외하는 `build/qa/smooth-camera/`에 있습니다.

창 크기 검사에서는 실제 브라우저의 `resize` 이벤트와 정지된 테스트 시계의 순서 차이가 드러났습니다. 이벤트 도착을 확인한 뒤 지연 타이머를 진행하도록 검사 코드를 보정했습니다. 단계 재생 검사도 테스트 시계를 정지한 뒤 필요한 시간만 진행하여 실제 검사 지연이 재생 시간에 더해지지 않도록 했습니다. 화면 이동이 끝난 뒤의 설명 시간을 기준으로 확인하며, 보정 후 전체 브라우저 검사가 통과했습니다.

## 재현과 산출물

~~~sh
npm run fixtures
npm run m1:examples
python3 scripts/evaluate.py run --output build/eval/<new-run>
python3 scripts/evaluate.py compare build/eval/m2-before-smooth-camera/results.json build/eval/<new-run>/results.json
S2S_EVAL_DIR=build/eval/<new-run> npx playwright test
npm test
~~~

현재 확인 파일은 `build/eval/m2/agent-parallel-tools.html`입니다. `build/examples/` 11개, `build/m1/` 6개, `build/eval/m2/` 24개를 같은 공통 템플릿으로 생성했습니다. 직전 평가 실행과 검토 양식 74개 파일은 `build/eval/m2-before-smooth-camera/`에 보존했고, 이동 전후 파일 해시를 확인했습니다. 현재 평가 기록의 엔진 해시도 생성에 사용한 스킬·렌더러와 일치합니다.

검증 대상은 오프라인 뷰어의 화면 이동과 저장된 설명 후보의 재생입니다. 기존 의미·근거 판정은 변경하지 않았으며 독립적인 사람 검토는 계속 대기 상태입니다.
