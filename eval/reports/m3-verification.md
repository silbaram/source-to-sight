# M3 규칙과 이유 구현·검증 — 2026-09-07

같은 동작의 조건·결과·이유·예외를 설명하는 소스 기반 `visual-primer`와 동작 페이지의 양방향 연결을 구현했습니다. **S3.1–S3.6 구현과 자동 검증을 완료했으며, 독립적인 사람의 사실·이해도 검토는 대기 중**입니다. 기존 M1/M1.5/M2의 미승인 상태도 유지합니다.

이번 작업에 앞서 M2와 부드러운 화면 이동 수정은 `94c03c5`로 `silbaram/ghostshark`에 커밋·푸시했습니다. 이 기록은 그 이후의 M3 구현을 검증한 결과이며, [선택한 실행 기록](../runs/2026-09-07-m3.md)의 엔진·후보·정답 해시로 실제 검사 대상을 식별합니다.

| 계획 항목 | 구현과 확인 범위 |
| --- | --- |
| S3.1 규칙 탐색 | [rule-checklist](../../skills/code-flow/references/rule-checklist.md): 입력·우선순위·자원·권한·생명주기·실패·종료를 실제 책임에 맞게 탐색. 이유는 코드의 처리 근거로 설명 |

| S3.6 평가 | 기존 동작 24개를 보존하고 여섯 프로파일의 규칙 사례 6개 추가. 규칙 27개를 역할·근거·수치·그림으로 검사하며 원본 동작의 필수 사실도 유지 |

`code-flow` 작성 도구 버전은 0.4.0입니다. 선택적 `rules[].rationale`과 `exceptions`를 아직 동결되지 않은 0.1.0 스키마에 추가했습니다. 이전 입력은 계속 유효하며 스키마·지침·렌더러 변경은 기존 검토 해시를 만료시킵니다. 일반 개념 `visual-primer`의 자유 작성 방식과 기존 캔버스의 작은 logic 픽스처도 유지합니다.

짝 생성은 두 입력과 출력 목적지를 검증하고 두 HTML을 모두 렌더링한 뒤 파일을 교체합니다. 각 파일의 교체는 원자적이며, 디스크 쓰기 중 오류가 발생하면 짝 생성을 다시 실행해야 할 수 있습니다. 기존 HTML에 적힌 검증 상태를 새 규칙의 근거로 사용하지 않습니다.

위 필수 대응 수는 페이지별 합계이며 같은 대상의 동작·규칙에서 각각 검사한 항목을 포함합니다. 저장소 전체의 서로 다른 구성 요소 개수가 아닙니다.

Python 검사는 미검토 초안, 제거된 검증 자료의 재사용 거부, 사실·범위·언어 변경, 다른 대상의 출력 보존, 수치가 이유나 예외에만 있는 경우, 의존 그림의 제거, 소스 변경, 잘못된 그림 참조, 출력 경로 충돌, 별도 위치에 설치한 두 스킬을 확인합니다. 규칙 평가에서는 ID 변경을 허용하면서 누락된 규칙을 다른 주장으로 중복 채우지 못하도록 검사하고, 수치·부호 변경과 이유 누락을 검출합니다. 그림 구성과 원본 동작도 사람 검토 해시에 포함됩니다.

브라우저 검사는 조건을 바꿨을 때의 결과·이유, 상태 전이·트리거, 근거 펼치기, 두 방향의 실제 파일 이동, 키보드, 다크모드 유지, 거부된 저장소·클립보드, 코드처럼 생긴 문자열의 비실행과 JavaScript 없는 설명을 확인합니다. 기존 캔버스의 부드러운 이동·자동재생·상세 패널·선택·확대·오프라인 검사도 모두 통과했습니다. 새로운 규칙 페이지의 첫 화면과 그림을 직접 확인했습니다.

## 확인할 결과와 재현

최신 결과는 `build/eval/m3/agent-parallel-tools-rules.html`입니다. 호출별/기본 한계와 오류 종류의 조건을 선택하면 결과·이유·예외가 바뀝니다. 상단 **동작과 협력으로 돌아가기**는 같은 대상의 `agent-parallel-tools.html`로 이동하며, 동작 페이지의 **규칙과 이유**로 돌아올 수 있습니다.

다른 유형은 `utility-retry-budget-rules.html`, `plugin-wrapper-unwind-rules.html`, `library-resize-callbacks-rules.html`, `event-async-lifecycle-rules.html`, `web-routing-fallbacks-rules.html`입니다. 실제 소스와 제외 범위는 [M3 소스 읽기 기록](../m3/discovery.md)에 있습니다.

~~~sh
npm run eval:rules -- --output build/eval/m3-next
S2S_EVAL_DIR=build/eval/m3-next npm run test:browser
npm test
npm run eval:compare -- build/eval/m2/results.json build/eval/m3-next/results.json --allow-suite-extension
~~~

재실행은 새 출력 경로를 사용합니다. 이번 작업은 `build/examples/` 11개와 `build/m1/` 6개도 현재 공통 자산으로 재생성했습니다. 기존 `build/eval/m2/`와 검토 답변은 보존했고, `m3-draft`와 `m3-ui-draft`는 개발 중 중간 결과입니다. 생성 HTML·전체 스크린샷·로그는 Git에서 제외되는 build에 두며, 선택한 기준 기록과 위 화면만 eval에 보존합니다.

## 남은 검토와 다음 구현

이번 평가는 저장된 후보의 재검증입니다. 대상 프로그램·모델 API를 실행하지 않았고 독립적인 모델 생성도 하지 않았습니다. 생성 시간·모델·토큰·비용은 추정하지 않았습니다. 근거 위치와 숫자가 맞아도 문장의 단위·적용 범위·이유·예외 전체가 정확하다고 자동 승인하지 않습니다. 같은 작성자가 만든 후보와 정답을 별도로 검토하고 처음 보는 독자의 핵심 규칙 이해를 확인해야 합니다.
