# 프로젝트 지도 UI/UX 변경 검토

2026-09-06 · 제안 및 인터랙티브 시안 · 공통 캔버스 UI 실제 생성 경로에 반영

**권고: 프로젝트 지도에는 캔버스 중심의 탐색 화면을 적용한다.** 현재 `agent-run.html`의 설명 내용과 근거 체계는 유지하고, `atlas` 계층의 화면 구성을 구분한다. 사용자는 **전체 구성 → 대표 흐름 또는 관심 부분 → 해당 동작의 상세 설명** 순서로 탐색한다.

[인터랙티브 시안 열기](atlas-prototype.html) · [기존 개발계획](../source-to-sight-evolution-plan.md) · [현재 렌더러 계약](../../skills/code-flow/references/renderer-contract.md)

## 1. 현재 화면이 상세 페이지처럼 느껴지는 이유

현재 `build/examples/agent-run.html`은 smolagents의 특정 실행 경로를 설명하는 `behavior` 페이지다. 프로젝트 전체를 분석한 지도는 아니다.

| 현재 구성 | 프로젝트 첫 화면에서 생기는 문제 | 변경 방향 |
| --- | --- | --- |
| 큰 제목, 목적, 입출력, 경고가 세로로 이어짐 | 주요 구성과 관계를 보기까지 내려가야 함 | 프로젝트 목적은 짧은 요약으로 압축하고 지도에 공간 할당 |
| 제한된 높이의 세로 다이어그램 | 전체 구성보다 한 동작의 순서를 읽는 느낌 | 남은 화면을 사용하는 이동·확대 가능한 지도 |
| 설명·근거 패널이 상시 공간 차지 | 아직 선택하지 않은 상세 정보가 탐색 공간을 점유 | 요소를 선택했을 때 상세 패널 열기 |
| 시나리오 재생이 다이어그램 하단에 있음 | 프로젝트에 어떤 주요 기능이 있는지 먼저 알기 어려움 | 대표 기능·흐름을 탐색 목록에서 먼저 선택 |
| 범위와 한계가 하단 접힘 영역에 있음 | 처음 보는 사용자가 설명 범위를 놓치기 쉬움 | 상단 범위 요약 + 선택 항목의 개별 신뢰 상태 + 상세 범위 패널 |

이는 현재의 동작 상세 페이지가 잘못되었다는 판정이 아니라, 프로젝트 전체 지도에 필요한 정보 배치가 다르다는 판단이다.

## 2. 참고한 제품과 관찰 범위

공식 문서를 기준으로 비교했다. Structurizr의 공식 화면 이미지와 현재 프로젝트 화면은 직접 시각 검토했다. n8n 문서는 브라우저에서 확인했다. LikeC4 공개 플레이그라운드는 로딩 이후 다이어그램을 확인하지 못했고, Dify 이미지 요청은 403으로 실패했다. 이 두 제품의 세부 동작은 공식 문서에 명시된 범위에서만 참고했다. 유료 계정이나 실제 실행 세션을 사용한 제품별 사용성 실험은 하지 않았다.

| 제품 | 공식 자료에서 확인한 패턴 | Source to Sight에 가져올 부분 | 적용 시 구분할 점 |
| --- | --- | --- | --- |
| [LikeC4](https://likec4.dev/dsl/views/) / [Dynamic views](https://likec4.dev/dsl/views/dynamic/) | 같은 모델을 관점·범위별 뷰로 보여주며 특정 시나리오의 동작 뷰를 별도로 정의 | 전체 구조와 대표 동작을 연결하되 관점을 명시 | 모든 프로젝트에 정해진 계층 수를 강제하지 않기 |
| [Structurizr viewer](https://docs.structurizr.com/server/diagrams/viewer) / [Animation](https://docs.structurizr.com/ui/diagrams/animation) | 다이어그램 간 이동, 확대·맞춤, 하위 뷰 진입, 단계별 노출 | 큰 지도, 현재 위치와 돌아가기, 설명을 따라가는 단계 전환 | 실시간 실행처럼 보이는 연출 대신 설명 순서임을 표시 |
| [n8n](https://docs.n8n.io/keyboard-shortcuts/) | 캔버스 이동·확대, 그룹 펼침·접힘, 노드 상세, 검색 중심 명령 모음 | 지도 조작, 검색, 관심 노드에서 상세로 진입 | 편집·배포·실행 버튼은 이 읽기 중심 제품의 주요 작업이 아님 |
| [Dify](https://docs.dify.ai/en/quick-start) | 워크플로 캔버스, 노드 선택 후 설정 패널, 분기·반복 영역 | 흐름을 주 화면으로 두고 선택한 부분의 맥락을 옆에서 설명 | 모델 설정 폼·실행 결과 화면을 소스 설명 UI에 그대로 옮기지 않기 |
| [LangSmith Studio](https://docs.langchain.com/langsmith/studio) / [사용 방식](https://docs.langchain.com/langsmith/use-studio) | 에이전트 그래프와 실행 상태 탐색, Graph/Chat 모드, 정보 상세도 조정 | 전체 구조와 상세 탐색의 정보 밀도 구분, 관심 단계 강조 | 실행 기록·토큰·시간·실제 상태는 별도 데이터 없이는 표시 불가 |
| [Dagster asset selection](https://docs.dagster.io/guides/build/assets/asset-selection-syntax) / [Catalog](https://docs.dagster.io/guides/observe/asset-catalog) | 계보 그래프의 상·하류 선택, 필터·검색, 그룹·코드 위치별 탐색 | 관계가 많을 때 주변 관계에 집중, 책임별 탐색 | 데이터 파이프라인 용어를 모든 프로젝트에 강제하지 않기. 최신 catalog 문서는 Dagster+ 기능임 |

아래 공통점은 위 자료에서 도출한 **이 프로젝트를 위한 설계 제안**이다. 모든 도구가 똑같은 기능을 제공한다거나 사용성 개선 효과가 측정되었다는 뜻은 아니다.

## 3. 추출한 공통 UX 패턴

1. **큰 그림이 첫 화면의 중심이다.** 제목과 설명은 방향을 잡아주고, 그래프가 관계를 설명한다.
2. **한 번에 모든 상세를 펼치지 않는다.** 구역 → 관심 요소 → 관련 동작으로 탐색 범위를 좁힌다.
3. **선택과 상세가 연결된다.** 지도에서 선택한 항목과 패널 제목·근거가 일치한다.
4. **이동 중에도 위치를 유지한다.** 현재 범위, 뒤로 가기, 전체 맞춤, 큰 지도에서는 미니맵을 제공한다.
5. **구조와 시간 순서를 구분한다.** 등록·의존 관계와 실제로 순서가 있는 설명은 같은 의미의 화살표로 취급하지 않는다.
6. **움직임은 시선을 안내한다.** 선택한 경로, 단계 전환, 초점 이동에 모션을 사용한다.

‘다이나믹한 화면’은 전체 선을 항상 움직이거나 입체 그래프를 돌리는 방식보다, **사용자의 선택에 따라 중요한 구성과 경로가 드러나는 방식**으로 구현하는 것이 적합하다.

## 4. 화면 정의 제안

### 공통 구성

| 영역 | 초기 화면 | 사용자의 행동과 결과 |
| --- | --- | --- |
| 프로젝트 헤더 | 이름, 한 줄 목적, 분석 범위·상태 | 범위 버튼 → 포함·제외·미확인·다음 탐색 위치 |
| 탐색 영역 | 전체 구성, 주요 요소 목록, 대표 기능·흐름, 검색 | 검색/항목 선택 → 해당 요소 강조 및 설명. 목록은 그래프의 텍스트 대안도 제공 |
| 지도 도구 | 현재 범위, 구성 보기/흐름 따라가기 | 관점 전환. 시나리오가 없으면 흐름 제어 미노출 |
| 중심 캔버스 | 주요 책임 구역, 공개 기능, 관계, 외부 경계 | 확대·이동, 선택, 관계 집중, 구역 펼침 |
| 상황별 상세 패널 | 초기에는 닫힘 | 역할 → 직접 연결 → 주요 동작/상태 → 근거 → 관련 상세 설명 |
| 설명 안내 바 | 대표 흐름 선택 시 노출 | 이전·다음·자동 넘김, 현재 단계의 쉬운 설명 |
| 지도 하단 | 범례, 확대·축소·전체 맞춤 | 큰 그래프는 미니맵에서 현재 위치도 확인 |

### 주요 상태와 전환

| 상태 | 화면 동작 | 돌아갈 때 유지할 것 |
| --- | --- | --- |
| 전체 구성 | 책임과 기능 관계를 표시. 순서 번호 없음 | 기본 관점 |
| 대표 흐름 | 선택한 시나리오의 단계와 관계 강조. 주변 구조는 약하게 남김 | 직전 관점·지도 위치 |
| 항목 선택 | 패널을 열고 선택 요소가 패널에 가려지지 않게 지도 이동 | 선택 항목, 카메라 |
| 관계 집중 | 직접 연결된 요소를 강조하고 주변 맥락은 약하게 유지 | 이전 범위·선택·카메라 |
| 하위 동작 설명 | 실제 생성된 `behavior` 페이지로 이동 | 상위 지도 범위, 선택, 카메라, 시나리오 단계 |
| 아직 없는 하위 설명 | 대상과 범위를 보여주고 생성 명령 복사 | 현재 지도. 클릭만으로 생성된다고 표시하지 않음 |
| 검색 결과 없음 | 결과 없음과 검색어 수정 안내 | 검색을 지우면 원래 구성 |
| 분석 일부 미확인 | 해당 노드·엣지·구역에 상태와 이유 표시 | 정상 정보도 계속 탐색 가능 |

### 디자인 규칙 초안

아래 수치는 시안의 출발점이며 실제 골든셋으로 조정한다.

- 현재의 밝은 바탕과 청록색 계열을 이어간다. 본문색 `#182f3b`, 강조색 `#087d72`, 배경 `#f8faf9`를 공통 토큰으로 둔다.
- 헤더에 다크 모드 온·오프를 제공한다. 기본은 밝은 화면이며, 사용자의 선택을 브라우저에 저장해 다시 열 때 복원한다. 다크 모드에서는 배경·패널·노드·연결·상태·입력 컨트롤을 함께 전환하며 탐색 상태를 유지한다. 저장소 접근이 제한된 환경에서도 현재 화면의 전환은 동작한다.
- 데스크톱 탐색 영역 약 224px, 선택 패널 약 326px. 나머지를 지도에 사용한다. 설명 패널을 고정 열로 예약하지 않는다.
- 노드는 책임 이름과 한 줄 역할을 우선 표시한다. 파일 경로와 식별자는 상세 정보에서 제공한다.
- 구역은 낮은 대비의 배경과 경계로 묶고, 외부 대상은 경계·문구로 구분한다. 외부라는 이유만으로 미확인 상태가 되는 것은 아니다.
- 실제 근거 상태는 노드·엣지·구역별로 표시한다. 관계 의미와 신뢰 상태를 색 하나에 혼합하지 않는다. 시안의 점선은 외부 경계 예시이며 최종 근거 범례를 대체하지 않는다.
- 선택·강조 전환은 약 180~250ms를 출발점으로 검토한다. 카메라 이동은 사용자가 요청한 선택·탐색에만 적용한다.
- 기본은 정지 화면. 자동 넘김은 명시적으로 시작한 경우만 동작한다. `prefers-reduced-motion`에서는 이동 애니메이션과 선 흐름을 제거하고 단계 변화는 유지한다.
- 좁은 화면은 접이식 요소 목록과 한 부분에 집중하는 지도를 제공한다. 패널은 하단에서 열리고, 전체 맞춤만 강제해 글자를 지나치게 작게 만들지 않는다.
- 드래그 외에도 확대 버튼·방향키·목록 탐색을 제공한다. 상세를 닫을 때 원래 항목으로 키보드 포커스를 돌린다.

## 5. 다양한 프로젝트에 적용하는 기준

화면 구성은 공통으로 유지하고 **실제 확인한 그래프 의미와 크기**에 따라 표시를 바꾼다. 아래 예시는 분석 결과를 미리 정하는 규칙이 아니다.

| 대상 | 전체 구성에서 설명할 후보 | 흐름이 있을 때 설명할 후보 |
| --- | --- | --- |
| 웹 앱·서비스 | 화면, 공개 기능, 책임 구역, 데이터·외부 연결 | 사용자 행동, 요청 처리, 이벤트 전달 |
| CLI·유틸리티 | 명령, 입력/출력, 옵션 처리, 독립 기능 | 실행 준비, 변환, 저장 |
| 라이브러리 | 공개 API·기능군, 공통 상태, 의존성 | 선택한 API의 사용 사례 |
| 프레임워크 | 코어, 등록·명세, 확장 지점 | 초기화, 등록, 훅 호출, 종료 |
| AI agent·harness | 실행 제어, 모델·도구 경계, 기록, 평가 구성 | 작업 시작, 판단·도구 반복, 종료, 평가 수행 |
| 데이터·이벤트 | 생산·소비, 변환, 저장, 스케줄·구독 관계 | 데이터 전달, 이벤트 처리, 재시도 |

노드 한 개도 정상적인 프로젝트 지도다. 독립 기능에는 관계선을 발명하지 않는다. 순서가 없는 관계에는 재생을 붙이지 않는다. 구역 수나 HTTP·Controller·Service·DB 계층을 공통 템플릿의 필수 항목으로 두지 않는다.

## 6. 코드와 계획에 반영할 범위

**제품 구조:** 사용자 확인에 따라 승인한 캔버스 UI를 공통 생성 템플릿에 적용했다. `atlas`는 전체 구성, `behavior`는 설명 범위의 구성으로 표기하며, 선택한 부분의 상세 설명·근거는 패널에서 확인한다. 공통 디자인 토큰, 선택·패널·근거 컴포넌트, IR·검증을 공유한다. 프로젝트 유형마다 별도 렌더러를 만들지 않는다.

| 우선순위 | 작업 | 기존 계획과의 연결 |
| --- | --- | --- |
| P0 | 지도 화면 정의·상태 전환·공통 토큰 확정 | 현재 검토 문서와 시안. M0 완료를 실제 지도 탐색 완료로 해석하지 않기 |
| P1 | 공통 캔버스 레이아웃, 검색·선택·관계 집중·상황별 패널·다크모드 | 실제 렌더러에 반영. 기존 IR과 근거 검증 재사용. M0 11개와 M1 6개 HTML 재생성 |
| P1 | 대표 기능 목록 → 선택한 흐름 → 생성된 상세 설명 연결 | M5 S5.3·S5.4. 미생성 항목은 생성 명령 제공 |
| P2 | 큰 구역 펼침, 지도 간 복귀 상태, 의미 있는 확대 수준, 작은 화면 보완 | M4·M5. 실제 크기별 지도 사례로 설계 |
| P2 | 실제 여섯 유형의 저장소로 지도 생성·이해 검토 | M5 S5.5. 시안 세 유형은 이를 대체하지 않음 |

현재 `nodes`, `edges`, `regions`, `subjects`, `scenarios`, `links` 및 근거 계약을 우선 활용한다. `subjects`를 자동으로 실행 시나리오로 취급해서는 안 된다. 기능과 시나리오의 명시적 연결이나 복합 구역 의미를 추가해야 한다면 스키마 변경으로 관리한다. 카메라·선택 같은 일시 UI 상태는 소스 근거 데이터와 분리한다.

캔버스 조작 참고용으로 [React Flow viewport](https://reactflow.dev/learn/concepts/the-viewport)를 확인했다. **라이브러리 교체는 이번 권고의 전제가 아니다.** 현재 SVG·Dagre와 오프라인 HTML 조건에서 필요한 조작을 먼저 검증하고, 복합 구역·접힘·성능 사례가 쌓인 뒤 의존성 추가 비용과 비교한다.

이 문서의 디자인을 실제 렌더러로 옮긴 결과는 [캔버스 적용 기록](../../eval/reports/canvas-viewer-verification.md)에 있다. M1 탐색 스킬·도구의 구현과 별개로 사람 검토 게이트는 대기 중이며, M5 전체 저장소 지도 탐색은 후속 범위다. 공통 UI 적용을 M4·M5 전체 완료로 해석하지 않는다.

## 7. 시안의 구현 범위와 검토 기준

[atlas-prototype.html](atlas-prototype.html)은 브라우저에서 직접 열 수 있다. 저장소에 있는 Noto Sans KR 글꼴을 상대 경로로 읽으며 외부 서버나 API를 사용하지 않는다. 파일 하나만 따로 배포하는 완성형 출력물은 아니다.

**구현한 상호작용:** 가상 AI 에이전트·프레임워크·독립 유틸리티 전환, 구성/흐름 전환, 목록·검색, 지도 이동·확대, 노드 설명, 관계 강조, 돌아가기, 설명 자동 넘김과 수동 단계, 미니맵, 작은 화면 패널, 모션 감소 대응, 다크 모드 전환·선택 저장.

**시안에 없는 제품 기능:** 실제 전체 저장소 분석, 실제 근거 검증, 하위 HTML 생성·연결, 복합 구역 펼침·접힘, 핀치 확대, 수백 노드 성능 검증, 페이지 간 상태 복원. 좌표는 화면 구성 검토를 위해 수작업으로 배치했다. 제품에서는 의미에 맞는 자동 레이아웃과 겹침 검증이 필요하다.

**제품 적용 전 통과할 기준:**

- 처음 보는 사람이 지도를 보고 프로젝트 목적·주요 책임·대표 기능을 설명할 수 있는지 관찰한다. 사용자 검토 결과 없이 이해도 개선을 수치로 단정하지 않는다.
- 여섯 프로젝트 유형, 한 노드, 순서 없는 관계, 반복·분기·외부 경계, 부분 분석을 검증한다.
- 노드·엣지·구역·시나리오의 근거 상태가 탐색 중에도 유지되고 서로 혼동되지 않는다.
- 노드·라벨·연결선이 겹치지 않고 상세 패널이 선택 대상을 가리지 않는다.
- 키보드와 목록으로도 모든 구성에 도달하며 작은 화면에서 문서 전체의 가로 넘침이 없다.
- 돌아갔을 때 범위와 선택을 잃지 않고, 흐름 전환 후에도 설명·현재 단계·강조가 일치한다.
- 기존 소스 비노출, 오프라인, 링크 대상·스냅샷 검증을 유지한다.

시안 브라우저 검토 결과와 스크린샷은 [시안 검증 기록](../../eval/reports/design/atlas-prototype-verification.md)에 기록한다.
