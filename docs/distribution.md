# 배포 파일 기준

이 저장소는 실행 가능한 스킬과 사용자 안내, 대표 예시를 관리합니다. 검증기와 생성 명령의 최소 회귀 검사는 저장소에서 유지하고, 평가 입력·실행 결과·시안은 기본적으로 별도 개발·검증 작업 공간에서 관리합니다. 공유 검토용으로 선택한 HTML과 화면 캡처는 `visual-checks/`에 보관합니다.

## 제품 배포 범위

다음 경로가 실제 사용자에게 제공되는 제품입니다.

- `skills/code-flow/`: 소스 기반 동작 설명 스킬, 렌더러, 스키마, 참고자료와 라이선스
- `skills/visual-primer/`: 개념·규칙 설명 스킬과 화면 템플릿
- `skills/codebase-atlas/`: 프로젝트 지도 생성 스킬
- `README.md`, `README.ko.md`, `docs/`: 설치·사용·지원 범위와 배포 기준 안내
- `assets/`: 저장소에서 바로 열어 볼 수 있는 대표 예시

스킬을 설치할 때는 각 `skills/<name>/` 디렉터리를 통째로 포함해야 합니다. `templates/vendor/`의 폰트·Dagre 파일과 라이선스도 런타임 렌더링에 필요하므로 제외하지 않습니다.

`skills/code-flow/scripts/vendor/`의 Python 검증기와 라이선스도 필수입니다. 이 검증기는 스킬 실행에 사용되며 생성 HTML에는 포함되지 않습니다.

## 개발·검증 보관 범위

검증기와 페이지 연결·맞춤형 그림 생성의 최소 회귀 검사, 작은 합성 입력과 대조 방법은 [검증 안내](../tests/README.md)에 있습니다. 이 검사들은 스킬 설치 대상이 아니며, 실행 결과와 브라우저 확인용 데모는 임시 작업 공간이나 추적하지 않는 `build/`에 생성합니다.

`visual-checks/`는 공유할 결과를 명시적으로 선택해 보관하는 시각 검증 디렉터리입니다. [유지보수 문서](../visual-checks/README.md)는 지도·기능 흐름·규칙 그림의 연결과 데스크톱·모바일 화면을 검토하기 위한 스냅샷이며, 스킬 설치 대상에는 포함하지 않습니다. 원본 분석 JSON과 소스 발췌는 이 공개 묶음에 포함하지 않습니다.

다음 종류의 과거 개발·검증 보관물은 제품 브랜치에서 제거했으며 별도 작업 공간에서 관리합니다.

- 평가 manifest·그래프·정답·검증 보고서·QA 스크린샷
- fixture와 고정 소스 출처
- 과거 평가 실행 도구와 대규모 회귀 검사
- 개발 계획·UI 시안·프로토타입
- 개발 환경과 검사 실행 설정

과거에 생성된 HTML·JSON은 제품 템플릿이 아닙니다. 지도·동작의 기본 템플릿은 `skills/code-flow/templates/flow-viewer-template.html`, 규칙 설명의 공통 탐색·근거 화면은 `skills/visual-primer/templates/`에 있습니다. 비즈니스 로직의 그림은 `visual-primer`의 맞춤형 버전 2 레이아웃으로 작성합니다. 저장소의 OAuth HTML은 설명 방식의 참고 예시이며 설치된 스킬에 반드시 존재하는 경로로 가정하지 않습니다.

## 생성 결과와 배포 결과 구분

생성되는 HTML·render JSON·스크린샷은 기본적으로 대상 프로젝트의 별도 작업 공간에 두고 제품 저장소에는 커밋하지 않습니다. 공유 검토용으로 선택한 HTML과 스크린샷만 `visual-checks/`에 커밋합니다. 스킬 설치에는 위 제품 배포 범위의 스킬 디렉터리를 제공합니다.

지도 빌더가 HTML 폴더 아래 `_internal/<지도 HTML의 확장자를 뺀 이름>/`에 보관하는 원본 JSON도 대상 프로젝트의 재생성용 데이터입니다. 소스 근거와 원본 그림 구성이 포함되므로 HTML 공유 묶음이나 정적 사이트에는 이 폴더 전체를 제외합니다. 별도 `--internal-dir`를 사용했다면 그 경로를 제외합니다. 폴더명만으로 공개 접근이 차단되는 것은 아닙니다.

`git archive`는 최소 회귀 검사와 `visual-checks/`를 포함해 지정한 커밋의 추적 파일 전체를 소스 묶음에 포함합니다. 현재 `.gitattributes`에는 외부 라이선스·벤더 파일과 이를 포함한 HTML 스냅샷의 공백 검사 예외만 있으며, 별도의 `export-ignore` 규칙은 없습니다. 과거 개발·검증 보관물은 제품 브랜치에서 이미 제거했습니다. 선택한 시각 검증 스냅샷을 제외한 생성 결과와 검증 기록은 대상 프로젝트의 별도 작업 공간에서 관리합니다.
