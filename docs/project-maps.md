# 프로젝트 지도 사용 안내

`codebase-atlas`는 저장소의 목적, 책임을 맡은 부분, 실제 관계와 대표 기능을 한 화면에 보여 줍니다. 호스트 에이전트가 소스와 문서를 읽어 내용을 작성하고, 공통 생성 도구가 근거 위치와 연결할 페이지를 확인해 오프라인 HTML로 만듭니다.

## 설치와 요청

설치와 첫 사용을 순서대로 진행하려면 [단계별 퀵스타터](quickstart.md)를 먼저 읽으세요. 이 문서는 지도 화면을 탐색하고 상세 페이지로 이동하는 방법을 설명합니다.

GitHub 저장소에서 모든 스킬을 함께 설치합니다. 프로젝트 지도에는 `codebase-atlas`와 `code-flow`가 필요하며, 규칙 설명까지 만들 때는 `visual-primer`도 사용합니다.

~~~sh
npx skills add silbaram/source-to-sight --global --skill '*'
~~~

폴더를 복사해 설치할 때는 각 스킬의 스크립트·참조 문서·템플릿·라이선스를 함께 보존합니다. Atlas는 실제 설치된 code-flow의 경로를 사용하며, 별도 위치는 `--code-flow-root`로 지정합니다. 검증기가 포함되어 있어 Python 3.10 이상만 있으면 실행할 수 있습니다. 상세 조립 명령은 [스킬의 조립 안내](../skills/codebase-atlas/references/assembly.md)에 있습니다.

~~~text
$codebase-atlas 이 프로젝트의 목적과 주요 구성, 대표 기능을 설명해 줘.
$codebase-atlas 이 라이브러리의 공개 기능과 내부 책임을 지도로 정리해 줘.
$codebase-atlas 에이전트 실행 제어, 도구, 모델, 기록이 어떻게 연결되는지 설명해 줘.
~~~

구역은 확인한 책임에 따라 정합니다. 작은 유틸리티는 노드 하나로 충분할 수 있고, 프레임워크·라이브러리·에이전트는 서로 다른 구성을 갖습니다. 디렉터리 위치만으로 호출 관계를 만들지 않습니다.

## 화면에서 확인하는 흐름

1. 상단에서 프로젝트의 목적과 분석 범위를 읽습니다.
2. **책임 구역**을 누르면 그 구성 요소와 실제로 연결된 이웃을 펼칩니다. 지도 구역 이름을 누르면 묶음의 근거도 확인할 수 있습니다.
3. **주요 기능**을 선택하면 담당 노드, 설명할 범위, 제외한 범위와 근거가 나옵니다.
4. 준비된 기능은 **동작 설명**으로 이동합니다. 해당 동작의 **규칙과 이유**에서는 핵심 비즈니스 로직을 큰 그림과 주제별 설명으로 살펴봅니다. 실제 분기·상태를 이해하는 데 도움이 되면 조건 선택이나 단계별 조작도 포함합니다. 정확한 조건·이유·예외와 소스 위치는 그림 아래 근거를 펼쳐 확인합니다.
5. **프로젝트 지도**로 돌아오면 선택한 기능과 구역, 확대·스크롤 위치가 복원됩니다. 화면 크기나 배치가 바뀌었다면 선택한 노드를 현재 화면 안에 다시 보여 줍니다.

미생성 기능에는 **생성 명령 복사**가 나옵니다. 복사한 요청을 호스트에 전달하면 정확한 대상과 범위로 상세 설명을 작성합니다. 브라우저의 버튼 자체가 분석이나 모델 실행을 시작하지는 않습니다. 새 상세 설명을 만든 뒤 지도를 다시 생성하면 링크가 갱신됩니다. 소스 시점·언어·대상·범위가 맞지 않거나 이 지도로 돌아오는 링크가 없는 기존 HTML도 생성 요청으로 표시합니다. 기존 상세를 지도에 연결하려면 그 내부 입력을 페이지 목록에 명시해 지도와 함께 다시 조립합니다.

지도에 실행 순서가 없는 경우 재생기는 나타나지 않습니다. 실제 순서를 추적한 상세 동작 화면에서 자동재생·배속·단계 이동을 사용합니다. 모든 지도는 공통 캔버스 템플릿의 다크모드, 검색, 이동·확대, 모바일 설명 패널을 사용합니다.

최종 탐색 흐름은 **프로젝트 맵 → 기능·상세 흐름 → 핵심 비즈니스 로직의 그림 설명**입니다. 마지막 단계는 [OAuth 예시](../assets/oauth-visual-primer-example.html)의 그림 중심 설명 방식을 코드로 확인된 규칙에 적용합니다. 주제마다 그림과 조작은 달라지며, 예시의 OAuth 내용이나 화면을 그대로 복제하지 않습니다. 기존 버전 1 레이아웃은 간단한 규칙 참고 화면으로 계속 열 수 있지만, 새 그림 설명은 맞춤형 버전 2 레이아웃을 기본으로 작성합니다.

## 사용 결과

`codebase-atlas`와 `code-flow`를 설치한 뒤 호스트 에이전트에 대상 프로젝트 설명을 요청합니다.

| 지도 유형 | 보여 주는 구성 |
| --- | --- |
| AI 에이전트 | 반복 제어, 실행 방식, 모델·도구·기록 |
| 프레임워크 | 플러그인 등록, 훅 호출, 결과 처리 |
| 라이브러리 | 캐시 정책, 기본 저장 구조 |
| 유틸리티 | 단일 문자열 정리 함수와 입력 계약 |
| 이벤트 | 신호 이름 공간, 등록·전달·참조 관리 |
| 웹 | 경로 등록·탐색, 보정, 외부 처리기 |

생성된 HTML은 대상 프로젝트에 대한 기록된 분석 결과입니다. 지도에 빠진 부분과 동적으로 결정되는 내용은 **설명 범위와 한계**에 표시합니다.

## 원본 데이터 보관과 재생성

출력 위치를 지정하지 않으면 `docs/atlas/<project-key>.html`을 사용합니다. 지도 빌더는 HTML 폴더 아래 `_internal/<지도 파일명에서 확장자를 뺀 이름>/`에 분석 원본을 자동 보관합니다. 예를 들어 `build/source-to-sight/project.html`의 원본은 `build/source-to-sight/_internal/project/`에 있습니다. 별도의 내부 위치는 `--internal-dir`로 지정합니다.

지도 원본 `atlas.internal.json`, 기능별 동작·규칙 원본 `*.internal.json`, 원본 그림 구성 `*.layout.json`, 입력과 HTML 경로를 연결하는 `pages.json`을 재사용합니다. 요청하지 않은 상세는 새로 만들지 않으며, 지도만 갱신해도 기존 상세 원본과 연결 목록은 보존합니다. 화면만 다시 만들 때는 이 JSON으로 렌더링하고, 소스가 바뀌면 영향을 받는 근거와 설명을 검토해 JSON을 갱신합니다. 자동 Git 변경 분석이나 HTML 부분 패치 기능은 아닙니다.

`render.json`은 검증 근거가 제거되거나 표시할 내용만 남은 화면용 데이터라서 원본 JSON을 대신하지 않습니다. `_internal/`에는 소스 발췌가 들어갈 수 있으므로 공유와 정적 사이트 게시에서 폴더 전체를 제외합니다. 자세한 명령과 기존 원본의 이전 방법은 [조립 안내](../skills/codebase-atlas/references/assembly.md#re-render-refresh-and-share)에 있습니다.
