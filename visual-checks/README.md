# 유지보수 문서 시각 검증

처음 프로젝트를 접하는 사람이 **프로젝트 구성·기능 요약 → 세부 처리·분기 → 선택한 처리의 규칙 그림**을 따라 이해할 수 있는지 검토하는 HTML 문서입니다.

[개선된 프로젝트 문서 열기](source-to-sight-maintainer/project.html) · [UI/UX 구성 기준](ux-review.md)

최상단에는 실행 환경·패키지·저장 파일·브라우저를, 아래에는 기능별 요청·결과와 2~3개의 역할 요약을 보여 줍니다. 역할 박스는 해당 기능의 세부 처리 목록으로, 처리 노드는 관련 규칙 그림으로 연결됩니다. 지도에서 상세 그래프를 반복하지 않습니다.

저장소를 내려받은 뒤 위 `project.html`을 브라우저에서 엽니다. 지도 1개, 기능 흐름 5개, 규칙 설명 5개가 상대 경로로 연결되어 있으므로 `source-to-sight-maintainer/` 디렉터리를 통째로 유지합니다. 별도 서버나 인터넷 연결은 필요하지 않습니다.


확인 범위는 데스크톱 1440px·모바일 390px의 밝은·어두운 테마입니다. 5개 기능의 규칙 11개를 네 화면 조건에서 탐색하는 44개 경로를 확인합니다. 같은 화면의 역할 요약과 해당 역할의 세부 처리 목록, 선택한 노드에 연결된 그림, 조건 비교 동작, 돌아올 때의 기능·선택 복원, 페이지 가로 넘침과 외부 네트워크 요청 여부를 검사합니다.

이 HTML은 생성 시점의 소스와 설명을 담은 검토용 스냅샷입니다. 화면 템플릿과 생성 코드는 `skills/`에서 관리하며, 이후 코드 변경이 이 문서에 자동 반영되지는 않습니다. 재생성용 원본은 로컬의 `build/source-to-sight-maintainer/_internal/project/`에 보관하고 Git에 포함하지 않습니다. 보관 기준은 [배포 파일 기준](../docs/distribution.md)을 참고하세요.


이번 UI 갱신에서는 기존 분석 스냅샷의 데이터를 유지하고 화면 템플릿만 다시
적용했습니다. 기능 카드 하단의 ‘처리 순서 따라가기’ 버튼을 제거하고, 각 묶음의
‘처리 상세 보기’로 상세 화면에 진입합니다. 선택한 묶음을
그림자·강조 테두리·배경색으로 구분합니다. 내부 노드를 살펴보거나 새로고침해도
해당 묶음의 강조를 유지하며, 다른 묶음을 선택하면 강조가 옮겨갑니다.
기록된 묶음이 없는 기능은 ‘처리 상세 보기’ 대체 링크를 유지합니다.
상세 화면의 기본 보기는 ‘처리 내용 보기’입니다. 선·화살표 없이 묶음별 카드를
데스크톱에서는 두 열, 좁은 화면에서는 한 열로 읽습니다. 카드에는 검증·조건 판단·
파일 읽기·파일 저장·문서 조립 등의 아이콘, 처리 종류, 대상, 설명을 표시합니다.
묶음이 길어도 자동 확대 비율은 85% 아래로 줄이지 않으며 스크롤로 읽습니다.
‘연결 보기’를 켜면 기록된 관계를 확인할 수 있고, ‘처리 순서 따라가기’와 경로 선택은
실제 기록된 시나리오를 따릅니다. 카드 위치만으로 실행 순서를 단정하지 않습니다.

이 저장소의 예제에는 DB·외부 API 동작을 추가하지 않았습니다. 실제로 HTML 내용을
조립하는 단계는 ‘브라우저 문서 조립’으로, 파일을 쓰는 단계는 ‘파일 저장’으로 구별했습니다.
공용 렌더러의 DB 읽기·저장, API 요청, 메시지 발행은 별도의 합성 주문 처리 예제로 검증합니다.
처리 종류가 기록되지 않은 기존 데이터에는 일반 처리 설명을 유지합니다.

처리 종류 변경은 Python 회귀 86개, 한·영·데스크톱·모바일·양테마의 처리 화면 8개와
기존 상세 탐색 8개로 확인했습니다. 화면 폭 변경 시 읽던 카드 유지, 첫 카드 노출,
연결 보기 왕복, 불확실성 표시, 선택 카드까지 포함한 본문 대비 4.5:1을 검사합니다.
기존 코드 비노출 검사 10개와 규칙 그림 탐색 검사 16개도 통과했습니다.

표현 방식은 [C4의 요소 종류·책임 명시](https://c4model.com/diagrams/notation)와
[BPMN의 작업 종류 표식](https://docs.camunda.io/docs/components/modeler/bpmn/business-rule-tasks/)을
참고했습니다. 이 화면은 해당 표준을 구현한 모델러가 아니며, 검토된 코드 동작을 읽기 위한 설명입니다.

공통 화면의 브라우저 회귀 검증은 별도로 생성한 합성 예제에서 수행했습니다.
코드 노출 검토에서는 갱신한 유지보수 HTML 11개도 데스크톱·모바일에서 직접 열어
설명과 근거 패널, 파일·줄 위치 유지, 가로 넘침과 외부 요청 여부를 확인했습니다.
갱신 후 포함된 데이터가 기존 분석 스냅샷과 동일한지는 렌더러로 검증했습니다.

지도와 상세 패널의 별도 함수명 표시는 제거했습니다. 구현을 찾을 때는 검색과
파일·줄 위치를 사용합니다. 생성 검증은 설명·조건·도움말·표시 데이터의 코드 식과
인라인 태그로 나뉜 발췌도 검사하며, 작성 가이드의 코드 블록·함수명 표시 권장도
제거했습니다. 생성 요청 복사와 정상 SVG 도형·파일 경로는 유지합니다.


선택 영역의 표면은 [Carbon의 중립색 계층](https://carbondesignsystem.com/elements/color/overview/)을
참고해 묶음 배경과 내부 카드의 밝기를 분리했습니다. 보라색 면은 실제 선택한 처리에만
적용하고, 굵은 테두리로 선택 상태를 표시합니다.
[W3C의 색 사용 기준](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color)과
[비텍스트 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast)을
참고해 색상 외에도 선택 상태를 구분할 수 있도록 했습니다.
합성 예제의 한·영, 1440px·390px, 밝은·어두운 테마 8개 조합에서 카드 경계와 선택
테두리의 인접 표면 대비 3:1 이상, 카드 본문 글자 대비 4.5:1 이상을
검사했습니다. 이는 해당 요소의 검증이며 전체 UI의 접근성 적합성 판정은 아닙니다.


상단 보기·묶음·경로 선택 UI는 하나의 배경으로 묶고, 하단 구분선과 여백으로
그래프 영역을 분리했습니다. 이중 선으로 보이던 그래프 외곽 테두리는 제거했습니다.
이 변경은 빌더의 공용 HTML/CSS 템플릿에 반영되어 이 저장소의 빌더로 새로
생성하는 문서에도 적용됩니다. 기존 검토용 HTML 6개에도 같은 템플릿을 다시 적용했습니다.


관계도 하단 중앙의 작은 손잡이를 위아래로 끌어 화면 높이를 320~1600px로
조절할 수 있습니다. 손잡이에 키보드 초점을 둔 뒤 위·아래 방향키로 40px씩,
Shift와 함께 누르면 100px씩 조절하며 Home·End는 최소·최대 높이로 이동합니다.
문구와 기본 높이 버튼은 제거하고 작은 손잡이만 표시합니다. 브라우저 저장소가
허용되면 선택한 높이가 새로고침 후에도 유지됩니다. 높이 변경은 노드 배치나
확대 비율을 바꾸지 않으며 드래그 시작 시 화면 중심의 그래프 위치를 유지합니다.


하단 범례에 노드의 노란 세로선이 처리 경계·종료를 나타낸다는 설명을 추가했습니다.
선택하지 않은 묶음 내부 노드에서도 경계·상태 종류의 세로선 색은 유지합니다.
수동 확대·축소에서는 노드와 묶음 제목을 동시에 맞추려는 자동 축소를 적용하지 않습니다.
설명 패널이 열려 있어도 요청한 배율을 유지하면서 선택한 노드를 중심으로 이동합니다.
현재 배율 숫자를 누르면 100% 실제 크기로 표시하며, 전체 맞춤 버튼은 별도로 유지합니다.
합성 예제의 한·영, 데스크톱·모바일, 밝은·어두운 테마에서 패널을 연 채로
100% → 120% → 100% 배율이 유지되는 것을 검사합니다.


상세 화면의 범례에는 ‘처리 종류’와 ‘노드’를 표시하고, 연결을 펼치면 ‘화살표’를 추가합니다.
노드에는 작은 상자 모양으로
선택 상태와 기록된 종류를 표시합니다. 화살표는 파란 실선으로 호출·제어, 청록 실선으로
데이터 전달, 회색 파선과 열린 화살촉으로 등록·의존을 구분합니다. 추정·미확인 연결은
노란 점선과 상태 문구를 함께 표시합니다. 선택·설명 중에는 선 굵기와 설명 테두리만
강조하여 관계를 나타내는 색이 유지됩니다. 지도, 프로젝트 구성, 기능 요약, 영역 연결과
설명 재생이 같은 관계색을 사용하며, 관계 유형은 읽기·쓰기·호출 등 텍스트로도 표시합니다.
실제 연결을 나타내지 않는 요청·결과 그림의 화살표는 중립색을 사용합니다. 노드의 노란
세로선과 화살표의 노란 점선 설명도 각 구역에 배치했습니다.
데스크톱은 좌우, 900px 이하 화면은 위아래 배치로 전환하며,
범례 아이콘은 보조 그림으로 처리하고 의미는 텍스트로 제공합니다.
