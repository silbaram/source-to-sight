# 프로젝트 구성과 기능별 처리 · UI/UX 검토

[수정한 문서 열기](source-to-sight-maintainer/project.html)

이 화면의 목적은 처음 보는 유지보수자가 프로젝트의 전체 구성과 각 기능의 처리 과정을 한 페이지에서 이해하도록 돕는 것입니다. 그룹의 기준은 결제·조회·문서 생성 같은 **실제 기능**입니다. 컨트롤러·서비스·DB는 해당 기능 안에서 일을 나누는 구성 요소로 배치합니다.

현재 배치를 유지하면서 “처리 박스를 누르면”, “아래에서 펼쳐 보세요” 같은 화면 사용 안내 문장은 제거했습니다. 본문은 프로젝트의 역할·입력·처리·결과를 설명하고, 이동은 버튼 이름·링크 표시·현재 위치로 전달합니다. 문서 생성과 탐색은 이 저장소의 실제 기능이므로 해당 설명은 유지합니다.

## 정보 배치

1. **최상단 — 프로젝트 구성:** 서비스·패키지·실행 환경·저장소·외부 연결을 그림으로 설명합니다.
2. **그 아래 — 실제 기능별 그룹:** 각 기능의 `들어오는 요청·데이터 → 만들어지는 결과`를 그룹 위쪽에 놓습니다.
3. **그룹 내부 — 주요 역할 요약:** 문서 생성은 `문서 조립 → 근거 검사 → 파일 저장`처럼 축약합니다. 상세 그래프의 내부 노드와 분기를 그대로 반복하지 않습니다.
4. **상세 페이지 — 세부 처리:** 역할 박스에서 그 역할에 포함된 처리 목록으로 연결됩니다. 이 단계에서 실제 처리 순서·예외 분기·전달 데이터·코드 위치를 설명합니다.
5. **로직 페이지 — 조건과 결과:** 상세 처리 노드의 판단 규칙이 왜 필요한지 그림과 짧은 설명으로 보여 줍니다.

이 저장소는 Agent Skills 패키지이므로 코딩 AI 실행 환경, 세 스킬과 공통 구현, 저장 파일, 브라우저를 보여 줍니다. 주요 기능은 프로젝트 문서 만들기 / 한 기능 설명 만들기 / 설명 검사·HTML 생성 / 판단 기준 그림 만들기 / 문서에서 기능·규칙 찾기입니다.

각 기능의 요약은 정확히 대응하는 동작 문서에 작성한 책임 그룹을 사용합니다. 그룹은 실제 세부 처리에 연결되며, 그룹 간 화살표는 원래 그래프에 있는 연결만 사용합니다. 같은 담당 구성을 공유한다는 이유로 다른 기능의 흐름을 합치지 않습니다.

## 연결과 조작

| 조작 | 보여 주는 내용 |
| --- | --- |
| 기능 바로가기 | 같은 페이지의 기능 요약 |
| 역할 요약 박스 | 그 역할에 속한 세부 처리 목록과 해당 처리 강조 |
| 전체 처리 보기 | 해당 기능의 모든 기록된 처리와 분기 · ‘전체 처리’ 선택으로 시작 |
| 표시 범위: 주요 처리 / 전체 처리 | 현재 기능에서 표시할 처리 노드의 범위 |
| 상세의 처리 노드 | 해당 지점의 데이터·규칙·코드 위치 |
| 조건·결과 그림 열기 | 선택한 처리의 판단 기준 그림 |
| 프로젝트로 돌아가기 | 읽던 기능 요약의 제목 |

기능의 나열 순서는 실행 순서가 아닙니다. 병렬 관계나 되돌아오는 연결을 직렬 처리로 바꾸지 않습니다. 요약 그룹이 없으면 입력·결과와 상세 링크를 유지하며, 상세 그래프를 그대로 복사해 채우지 않습니다. 경로 선택은 상세 페이지에 있습니다.

## 참고한 설명 방식

- [React · Thinking in React](https://react.dev/learn/thinking-in-react): 하나의 구체적인 기능을 구성 요소와 데이터 흐름으로 나누어 설명하는 접근을 참고했습니다.
- [Red Blob Games · A* 소개](https://www.redblobgames.com/pathfinding/a-star/introduction.html): 입력과 결과를 시각적으로 연결하고, 그림 바로 옆에 짧은 설명을 두는 방식을 참고했습니다.
- [NN/g · Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/): 기본 이해에 필요한 기능 흐름은 먼저 보여 주고, 상세 규칙과 근거는 선택해서 읽도록 적용했습니다.

기능별 그룹과 프로젝트 구성의 배치는 사용자가 명확히 설명한 요구를 기준으로 했습니다. 사이트의 화면을 그대로 복제하지 않았습니다.

## 확인 범위

데스크톱·모바일, 밝은·어두운 테마에서 프로젝트 구성과 기능별 요청·결과·박스를 확인합니다. 기능의 정확한 범위, 직접 노드 이동, 규칙 그림, 돌아오기, 오래된 상세의 미리보기 제외, 외부 네트워크 요청과 가로 넘침도 검사합니다. 자동 검사와 캡처가 실제 사람의 이해를 보증하는 것은 아닙니다.
